# チャンネル文体・視覚デザイン・パッケージ スタイルガイド（STYLE_GUIDE）

本ガイドは「AIが書いても人間らしい番組品質を保ち、YPP審査に一発通過する」ための現行2フォーマット横断の文体・デザイン基準。
各フォーマット固有の舞台設計・背景極性・監査定数は各ハーネス正本（`harnesses/stickman-collage/`・`harnesses/plan-e-macro-econ/`）
およびコード定数を参照する。

---

## 1. 日本語ナレーション文体と台本方針（固い床 × 自由舞台）

### 1.1 チャンネル別の語り口指針と固い床
- **ch1『バグる棒人間』（`stickman_collage` v2.1・人間や世界のバグ・奇妙な仕組み／多ジャンル）：** 丁寧な敬体（「です・ます」）を基調に、
  人体・進化・科学・歴史・生き物・言葉・確率・AI・社会・心理など幅広い題材を、説教臭のない軽快で知的な並走感で語る。
- **ch2『経済の赤ペン』（`planE_macro_econ` v3.1・お金とインセンティブの構造解剖／多ジャンル）：** 丁寧な敬体（「です・ます」）を基調に、
  恋愛・医療・スポーツ・アート・エンタメ・冠婚葬祭・家電・歴史・教育・都市・経済など幅広い題材について、
  事実とインセンティブの矛盾を静かに刺す**乾いた知的シニカル調**で語る。
- **固い床（全フォーマット共通・機械検証対象）：**
  - 冒頭の挨拶・自己紹介・登録/高評価依頼ゼロ。
  - 末尾の終了合図語（「いかがでしたでしょうか」「ご視聴ありがとうございました」等）および禁止語尾（「〜だぜ」「〜なのぜ」）ゼロ。
- **自由舞台（テーマに合わせて自在）：**
  - 導入の切り口、章立て・展開ブロック、リフックや章末の形、短文連打や長文の緩急リズム、尺の長さは固定せず、
    その回が一番面白くなる構成を選ぶ。専門用語や統計は視聴者の生活実感が浮かぶ口語へ噛み砕く。

### 1.2 文体と推敲の自由度
- **NG語リストによる細かい表現縛りは設けない。** 固い床（冒頭挨拶ゼロ・終了合図語ゼロ・禁止語尾ゼロ・2ファイル整合・読み上げ原稿の純度）
  さえ守れば、モデルの自然な日本語表現力を最大限に活かす。言い回しの良し悪しは音読リライトと聴感で判断する。

### 1.3 2ファイル分離と機械検証（固い床）
- `02_script_display.md`（表示・演出・概要欄用出典メモ）と `03_script_reading.md`（TTS読み上げ専用原稿）を
  同一チャンクID・内容整合で分離し、`03_script_reading.md` へのト書き・英語指示・Markdown装飾混入をゼロにする。
- 冒頭30〜90秒を中心に人間が音読リライトし、`pipeline/scripts/lint_script.py` で **固い床 ERROR 0** を確認する
  （TTS前処理 WARNING〔誤読漢字・桁カンマ・%・未カナ英字〕と尺・リズム指標は参考材料。WARNING 0 は強制しない）。

### 1.4 視聴維持と「間」の制作ガイド（制約ではなく参考指針・lint のエラー条件にしない）
- **冒頭15秒の約束:** タイトル・サムネの約束（`clickConfirmPromise`）に15秒以内で触れ、期待値をずらさない。
- **3分目のリフック:** 導入の熱が切れる3分前後に、新しい謎・反転データ・予告で2本目のフックを置く。
- **中盤の転換点:** 中盤で視点や前提をひっくり返す山場を作り、後半へ進む理由を与える。
- **要所の「間」:** 結論・反転・オチの前後に絞って効かせる（乱発すると間延びする）。
  - 短い呼吸（〜0.5秒）は 03 本文の書き方で作る：句点で切る、短い一文を独立させる、問いと答えを別の文にする。
    「……」「――」は余韻の表記として使ってよいが、ElevenLabs v4 では無音はほぼ伸びない（実測）。
  - 長い間（0.8〜1.5秒）は台本の外で入れる：ch1 は shot の `pauseAfterSec`、ch2 は chunk の `pauseAfterSec`。
  - 「（間）」「[pause]」「【間】」などのト書き・タグは使わない（固い床 ERROR）。

## 2. Remotion 2D ビジュアル・テロップ・音響規格

- **画面規格:** `1920 × 1080` / `30fps`、重要テキスト・図解は**内側90%セーフゾーン**内に配置（`VIDEO_SPEC`）。
- **フォント規定:** `Noto Sans JP` / `Noto Serif JP` / `Zen Maru Gothic` / `Yomogi` / `Playfair Display` 等の
  **SIL OFL 1.1 または Apache 2.0** 限定（Adobe / Morisawa 同梱禁止）。
- **脱 AI Slop 3大NG（即却下）:**
  1. 直線 `<line>`/`<circle>` の幾何学棒人間
  2. Tailwind slate 系グレー（`#0F172A` / `#1E293B` 等）・`borderLeft` 帯・`borderRadius: 999` ピル型など SaaS 風 UI 連打
  3. 下段の常時ダーク帯ボックス字幕（抜け感アウトライン字幕 `CleanSubtitle` / `CollageSubtitle` を使用）
- **2層テロップ規格:**
  - 下段ベース字幕：`24〜32 px`、**1行 14〜18文字目安・最大2行**、コントラスト比 `4.5:1` 以上。
    読み上げ原稿と表記差を除き**一言一句一致**（要約・削除・言い換え厳禁、長文は文節で複数セグメント分割）。
  - 中央・上部キーワード：見出し/強調数値 `48〜64 px`（図解・語単位 `cue()` 連動）。
- **テンポ・背景極性：** 各ハーネスの機械監査基準（`stickman_collage_validator.py` / `PLAN_E_AUDIT_RULES`）に従い、
  長時間の静止や単一極性の連続を避け、重要結論直前に意図的な「間」を挟む。
- **音声マスタリング：** 統合ラウドネス `-14.0 LUFS`、トゥルーピーク設定 `-1.4 dBTP`（MP4 AAC 実測 `<= -1.0 dBTP` 保証）、48kHz。

## 3. パッケージ（タイトル・サムネイル）規格

- **台本前仮確定（Gate 1）:** 執筆前にサムネ構図・コピー案・`clickConfirmPromise` を仮確定し、
  `.agents/skills/thumbnail-design/SKILL.md`（v2 自由舞台 `<Still>` TSX）に従って `build_thumbnail.py --validate-only` で検証する。
- **企画:** 特定ジャンルに閉じず（ch1・ch2 の題材範囲は §1.1）、広い視野で多ジャンルから切り込む案を出す。
- **タイトル:** **全角30文字前後**を目安に、英語直訳調（「〜の隠された真実」「なぜ〜は壊れているのか」等）を避け、
  日本語としてクリックしたくなる自然な一文にする。
  「検索KW先頭」「`【】`活用」は必須ではなく**任意オプション**。
- **サムネイル:** **上限20文字・2行以内**。スマホ縮小時に0.5秒で読める文字サイズを保つため、**3〜10文字程度**の短いコピーを推奨する。
  視覚要素・小道具や画面内の小文字を盛りすぎるとスマホ縮小時に広告チラシや資料に見えてスルーされやすいため、**主役・モチーフは2〜3個程度に絞り、細かい文字も極力省くことを推奨**する。
  **書体は固定しない**（ゴシック・明朝・手書き系など、題材とハーネスv2の自由舞台方針で選ぶ。ライセンスは §2 フォント規定）。
  企画ごとに全く別物の世界観・構図・タイポ配置・配色を自由に発明し、大差2〜3案では絵面だけでなく切り口・フック軸ごと検証できるよう**コピーも各案に最適な文言を振ることを推奨**する。
  4大トリガー（数字・損失回避・意外性・自分ごと化）から1〜2種。右下再生時間バッジ領域（`1920×1080` 右下 `220×84px`）回避、
  **168×94px 縮小スクイント**と YouTube 模擬比較シートでのクロス目視 QA 必須。本番出力 `3840×2160`（50MB以下）。
- **タイトルとサムネの関係:** タイトルの丸写しは避けつつ、**主題語1〜2語の自然な共有を推奨**し、
  0.5秒で文脈が噛み合う状態にする（機械検証は丸写しのみ Error、言い換えに近い重複は Warning）。
- **画面内・サムネ内の出典表記ゼロ:** 出典・クレジットはすべて YouTube 概要欄に集約する（オーナー方針・変更不可）。
