1.2 海外の超ミニマル型（0〜3語）を日本にそのまま持ち込むとCTRが落ちる理由

海外シート（01・03）では32本中40.6%（13本）がメイン12文字以下、9.4%（3本：01-#05・01-#09・01-#12）がテキストゼロであり、03-#07の「yet...」（1.51倍）、03-#08・03-#09の「WHOOPS」、03-#13の「GONE」（1.61倍）、01-#02の「TARARRE」（4.29倍）のように、0〜1語と強烈な象徴ビジュアルだけで数百万再生を獲得している。一方、日本ベンチマーク32本でテキストゼロは0.0%（0本）であり、海外の超ミニマル型をそのまま日本市場へ持ち込むとCTRが低下しやすい。その背景には3つの認知的・文化的・構造的要因がある。   

第一に、英語アルファベットと日本語漢字・仮名混じり文の視覚情報密度と眼球運動特性の違いである。眼球運動研究では、英語の熟達読者の知覚範囲（perceptual span）は注視点の右約14文字に及ぶ一方、アルファベットは1文字あたりの意味密度が低いため、サムネイル内で0.5秒スキャンに耐える上限は「3〜5語（15〜25文字程度）」にとどまる。対照的に日本語は表意文字の漢字と表音文字の仮名が混在し、読み手の視線は意味抽出のためひらがなよりも漢字へ優先的に着地する。漢字の平均注視時間は約168ミリ秒と英語より短く、漢字仮名混じり文の知覚範囲は研究条件により幅があるものの注視点の右約6文字（全体有効視野10〜17文字程度）とされる。すなわち英語圏で「3語」しか詰め込めない0.5秒・2注視の認知枠内に、日本語話者は「脳を洗浄する／ヤバい休息（12字）」や「なぜ円はここまで弱いのか（12字）」といった完結した因果フックを瞬時にチャンク認識できる。にもかかわらず日本語サムネで1語（例：「終了」「まだ…」「バグ」）しか置かないと、認知負荷を下げるどころか日本語話者が無意識に期待する情報利得を大幅に下回り、意味を掴む前にスクロールされてしまう。   

第二に、日本固有の「テレビテロップ（インパクト・キャプション）視覚文化」である。1990年代後半のバラエティ番組で普及したテロップ文化は、画面上の大きな強調テキストから瞬時に文脈・感情・見どころを把握する受容習慣（親近性仮説・効率性仮説）を視聴者に定着させた。片付けコンサルタント近藤麻理恵氏の事例でも、英語圏向けチャンネル「Marie Kondo」は白基調の無文字写真であるのに対し、日本向け「こんまりちゃんねる」ではサムネイルだけで動画内容を把握できる大型テキスト配置へ明確にローカライズされている。日本のモバイル視聴者はタイトルを読む前段のスクリーニングとしてサムネ内コピーで「自分ごと性」を一次判定するため、テキストゼロや抽象1語のみでは判断の土台に乗らない。   

第三に、「ブランド既知性」の非対称性である。海外で無文字や1語が成立する01-#05・01-#09（The Paint Explainer）、01-#12（Casually Explained）、03-#07（How Money Works）、03-#08・03-#09（ColdFusion）はいずれも数百万登録者クラスの既知ブランドであり、視聴者が「この画風／この暗色ポートレート＝あのチャンネルだ」と即座に識別できるからこそタイトルへ視線が移る。日本市場で唯一の5文字外れ値である02-#16（195.82倍、「天才の習慣」）も、アインシュタインの顔という世界共通アイコンと「天才」の漢字2文字が直結していた特例であり、無名の新規非属人チャンネルが抽象1語で模倣すると単なる「情報不足の未完成サムネ」と誤認されるリスクが高い。

2. タイトル × サムネの分業パターン解剖：オープンループの6類型
2.1 重複度別・分業パターン別の定量パフォーマンス

行動経済学者ジョージ・ローウェンシュタイン（1994年）の情報ギャップ理論が示す通り、好奇心は「既知の情報」と「知りたい情報」の隙間に生じる認知的な不快感であり、優れたYouTubeパッケージはタイトルとサムネイルを独立したラベルではなく「1つの未解決の問いを半分ずつ分担する装置」として機能させる。Paddy GallowayのG.A.P.S.フレームワーク（Action Gap / Ambiguity Gap / Promise Gap / Status Gap）やAdobe公式ガイドラインの「タイトル隠し／画像隠し／同時閲覧の3視点確認」も、単純な文言重複を排した相互補完を原則としている。   

添付64本すべての動画タイトルとサムネイルコピーを突き合わせ、重複度（zero＝完全非重複、low＝主題アンカー1語のみ共有し残りは別文脈、med＝半分程度重複、high＝ほぼ同語反復）と分業パターン（7類型：P1〜P7）をクロス集計した結果、海外と日本では最適な重複度に明確なズレがあることが浮かび上がった。

3.1 APCA知覚コントラスト監査：なぜ「暗背景×赤文字」がサムネを殺すのか

構図アーキタイプを定義する前に、2Dコード駆動で最も見落とされやすい色彩工学上の落とし穴を潰す必要がある。現行の法的アクセシビリティ基準であるWCAG 2.1のコントラスト比は物理的な相対輝度差のみを評価し、暗背景に明色文字を置いた際のハレーション（滲み）や文字サイズ・太さを考慮しない。これに対しWCAG 3.0の候補モデルであるAPCA（Accessible Perceptual Contrast Algorithm）は、背景明暗の極性（白地に黒 vs 黒地に白）と人間の知覚特性を組み込んでLc値（知覚コントラスト指数）を算出する。   

ch1およびch2の候補配色17組に対してWCAG 2.1比とAPCA Lc値を算出した結果、重大な「WCAG偽合格の罠」が確認された。純黒背景（#050505）に純赤文字（#FF0000）を置いた場合、WCAG 2.1は5.10:1でAA基準を通過するにもかかわらず、APCAはLc -37.5（不合格：168×94px縮小時に判読困難）となる。同様にch2のダークスレート背景（#14181F）に赤ペン文字（#E62E2D）を直接置いてもAPCA Lc -32.0（不合格）に落ちる。暗背景上では赤の輝度知覚が黒へ沈み込み、小画面で輪郭が消失するためである。   

対照的に、新聞紙白（#F2ECE1）の上に濃い赤ペン（#C8102E）を置くとAPCA +66.2（太字見出し合格）、さらに赤ペン帯（#C8102E）の上に白抜き文字（#FFFFFF）を載せるとAPCA -82.4（極めて高い視認性）へ一気に改善する。暗背景で強調色を使いたい場合は、ch1ならバグイエロー（#FFD600、APCA -83.8）やエレクトリックシアン（#00E5FF、APCA -79.0）、ch2ならエディトリアルゴールド（#F5C542、APCA -74.2）または赤ペン帯＋白抜き文字（-82.4）を採用するのが光学的に正しい。

3.4 「AI画像生成不使用」で手触りと実在感を出すRemotion 2Dプロシージャル描画仕様

Remotion <Still> で通常のHTML/SVGを描画しただけでは、幾何学的に均質すぎて「PowerPoint／SaaS広告／安価な自動生成テンプレ」に見えやすい。AI画像生成を一切使わずに手作業のエディトリアル質感を実現するため、ハーネスv2では以下の5つのプロシージャル描画・運用仕様を標準組み込みとする。

rough.js＋決定論的シードによる手描きSVGパス（棒人間・赤ペン・グラフ）： 直線・円・矢印・取り消し線はすべてrough.jsの2パス手描きアルゴリズム（わずかなオーバーシュートと線揺らぎ）でSVG <path> 化する。実装上の重要な注意点として、rough.jsはseed: 0をfalsy評価してMath.random()にフォールバックし、描画の決定論性が壊れる仕様があるため、必ずvideoIdのハッシュ等から生成した1以上の正の整数（seed >= 1）を強制注入する。縮小耐性を確保するため、720p基準で赤ペンの最小ストローク幅は8〜14px（4K基準24〜42px）、棒人間の輪郭線も6〜10px（4K基準18〜30px）を下限とする。   

SVGフィルタ（<feTurbulence>＋<feDisplacementMap>）による紙質・チョーク・インク滲み： <svg><defs><filter>内にパーリンノイズを生成する<feTurbulence>と画素変位を与える<feDisplacementMap>（scale: 2〜5）を定義し、棒人間・赤ペン・紙面背景へ適用する。背景の新聞紙・黒板へ高周波ノイズを低不透明度（4〜8%）で重ねることでデジタルのベタ塗り感を消す。なお、日本語見出しフォントへ強い変位をかけると漢字画数が潰れるため、テキスト用変位はscale <= 2（720p換算）に制限する。   

ネット収集した実写写真の「非ストック化」変換（<feColorMatrix>デュオトーン・ハーフトーン・破り紙）： フリー写真素材を無加工で貼ると量産ストック動画に見え、YouTubeの「非真正コンテンツ」審査リスクも高まる。ハーネスv2では全実写素材にSVG <feColorMatrix>による高コントラスト・デュオトーン化や新聞写真風のハーフトーン加工、および決定論的ポリゴンによる破り紙風clip-path＋白縁（紙の厚み）＋ドロップシャドウを自動適用し、収集素材をチャンネル固有のコラージュ美術へ変換する。   

日本語フォントのローカルバンドルとdelayRender()固定： @remotion/google-fontsにはjapanese等のCJK名前付きサブセット指定時に例外を投げる既知の不具合が報告されているため、CDN動的読込には依存せず、オープンライセンス日本語フォント（ch1見出し：Noto Sans JP Black / Dela Gothic One、手描き注釈：Zen Kurenaido / Klee One；ch2見出し：Noto Serif JP Black / BIZ UDMincho / Noto Sans JP Black、赤ペン手書き：Yuji Syuku / Zen Kurenaido）をpublic/fonts/にローカル同梱し、staticFile()とdocument.fonts.ready＋delayRender()で読込完了を保証してからレンダリングする。   

「サムネ内クレジット非掲載」と権利安全の運用境界： サムネ画面内に著作権・出典クレジットを載せない制約を法的に安全に運用するため、素材は①政府統計数値や単純な表・グラフ（著作権の対象外であり政府標準利用規約でも自由利用可能）を自社SVGで再描画したもの、②CC0／パブリックドメイン／商用クレジット不要フリー素材（肖像権・パブリシティ権侵害のないもの）、③公知の事実・数値からコード生成した自社製新聞風モックアップ紙面に原則限定し、すべてのデータ出典・素材クレジットは動画概要欄へ集約する。第三者の著作物や報道写真をそのまま利用する場合は著作権法32条の引用要件（出所明示の慣行適合性）や肖像権リスクが生じるため、報道当事者の写真を使う企画はパブリックドメイン確認済みの公的機関写真等に限定し、素材メタデータJSONにライセンス種別と概要欄用クレジット文を必須記録する。

5.1 Remotion <Still> レンダリング基本仕様と16:9セーフゾーン座標

ハーネスv2は、企画・台本データから生成された構造化JSON（ThumbnailSpecV2）を単一情報源（SSOT）とし、Remotionの<Still>コンポーネントおよびNode.js APIのrenderStill()を用いて1回のジョブで4種類の成果物を決定論的に出力する。具体的には、①YouTubeアップロード用マスター（1280×720 JPEG、jpegQuality: 88〜92、<= 1.8MBでモバイル2MB上限と720p解像度下限を同時クリア）、②4Kアーカイブおよび高精細QAマスター（論理1280×720設計に対しscale: 3で3840×2160 PNG出力）、③YouTube UIオーバーレイ（角丸・右下再生時間バッジ・ライト／ダーク背景）を合成した168×94pxモバイル実寸プレビューPNG、④添付ベンチマーク02（ch1用）または04（ch2用）の15枚の中央ランダムスロットへ自社案を埋め込んだ競合16枚比較シートPNGである。複数案（A/B/C）の一括レンダリング時はopenBrowser()で起動したブラウザをpuppeteerInstanceへ渡して再利用する（Remotion公式仕様上、生のPuppeteerインスタンスは非互換であり必ずopenBrowser()を使用する）。

5.4 YouTube公式「テストと比較（Test & Compare）」大差3案（A/B/C）振り方テンプレート

YouTube Studio（PC版・上級者向け機能有効化済）の「テストと比較」は2025年12月のグローバル展開以降、長尺動画に対してサムネイル単独・タイトル単独・タイトル×サムネイル同時パッケージの最大3案比較に対応している。運用にあたっては以下の4つの公式ルールおよび実務制約を厳守する。   

勝敗判定は「視聴時間シェア（Watch Time Share）」： クリック率が高くても冒頭で離脱される誇張案は敗北し、インプレッションあたりの総視聴時間を最大化する「期待値一致度の高い案」が勝つ。   

スロットA（1番目）の順序重要性： 統計的有意差がつかず「判定不能（Inconclusive）」で最長2週間が終了した場合、1番目に登録した案がデフォルトとして維持される。そのため最も堅実かつ視聴維持率が見込める本命案を必ずスロットAに配置する。   

途中編集の厳禁と解像度統一： テスト期間中にタイトルやサムネイルを1文字でも編集すると実験は即時自動終了する。また1案でも720p未満が混在すると全案が480pへ強制ダウンスケールされる。   

色違いテストの禁止と構図・訴求軸の完全分離： 微差のバリエーションは統計的分離が遅れ判定不能になりやすい。ハーネスv2では、3案で必ず「異なる構図アーキタイプ」「異なる背景明暗」「異なるオープンループ訴求軸」を割り当て、3案相互のdHash距離を>= 18に引き離す。
